# OfficeWeave 全体ロードマップ

本書は開発の進行順序と、現在地を記録する。
Phase の順序と内容を変更する場合は、本書を更新したうえで行う。

## Phase 一覧

| Phase | 目的                | 主な成果                                          |
| ----- | ----------------- | --------------------------------------------- |
| P0    | プロジェクト契約          | ビジョン、原則、命名、ロードマップ、Agent 運用                    |
| P1    | ローカル開発基盤          | コンテナ構成、アプリケーション雛形、データベース、起動コマンド               |
| P2    | 品質基盤              | テスト、Lint、セキュリティ検査、依存監査、CI                     |
| P3    | UI・多言語基盤          | 日本語・英語、基本レイアウト、デザイントークン、アクセシビリティ              |
| P4    | Identity          | ログイン、利用者、組織、部門、所属、権限                          |
| P5    | Portal            | ホーム、ナビゲーション、お知らせ、公開範囲、既読                      |
| P6    | Calendar          | 個人予定、共有予定、設備・備品、予約                            |
| P7    | Requests          | 申請、承認、差し戻し、履歴、代理処理                            |
| P8    | Documents         | 文書、添付ファイル、分類、アクセス制御、検索                        |
| P9    | Notifications     | アプリ内通知、メール通知、配信設定                             |
| P10   | Integrations      | REST API、Webhook、外部認証、インポート・エクスポート            |
| P11   | Operations        | 監査、バックアップ、復元、アップグレード、運用診断                     |

| P13   | Managed hosting   | 需要が確認された場合のみ設計・実装                             |

## P0 のタスク

| Task  | 内容                                | 状態  |
| ----- | --------------------------------- | --- |
| P0-T1 | プロジェクト契約とロードマップを文書化する             | 完了  |
| P0-T2 | code-pact を初期化し、P0 ロードマップを登録する         | 未着手 |
| P0-T3 | Agent 向け read/write scope と禁止事項を固定する | 未着手 |
| P0-T4 | OSS ライセンスと商標方針を決定する               | 未着手 |
| P0-T5 | 技術バージョンの選定基準と更新方針を固定する         | 未着手 |
| P0-T6 | P0 全体の整合性を検証し、P1 へ移行する            | 未着手 |

## P0 の実行境界

各タスクの範囲を、着手前に次のとおり限定する。
契約文書そのものが目的化しないよう、いずれも必要最小限にとどめる。

```text
P0-T2:
  code-pact の最小初期化と、既存 P0 ロードマップの登録だけを扱う。
  別の開発制御ツールを比較、導入、併用しない。
  code-pact を OfficeWeave の実行時依存へ追加しない。
  将来 Phase の詳細タスクは登録しない。

P0-T3:
  全タスク共通の禁止事項と、タスクごとに read/write scope を定義する形式だけを固定する。
  まだ存在しないアプリケーションのファイル配置を先に列挙しない。

P0-T4:
  ライセンス、著作権表示、製品名の利用方針だけを決定する。
  商用契約やホスティング契約は扱わない。

P0-T5:
  P1 で使用する技術バージョンの選定基準、対象系列、更新方針、
  および着手時点の候補バージョンを記録する。

  公式のサポート状況、配布物の存在、利用環境の CPU アーキテクチャへの対応など、
  アプリケーションを生成せずに確認できる事項を調査対象とする。

  このタスクでは、アプリケーション、コンテナ定義、Compose 構成、
  依存定義ファイル、ロックファイルを作成しない。
  本番インフラや性能設計も扱わない。

  実際に使用する固定値と、コンテナビルド、アプリケーション起動、
  データベース接続の証跡は P1-T1 で確定・記録する。
  P1-T1 の実測で候補が成立しない場合は、理由を記録したうえで候補を変更する。

P0-T6:
  P0 の契約間に矛盾がないことを検証し、次の実行 Task を P1-T1 へ移す。
```

## 現在地

```text
現在の Phase:      P0
直近完了 Task:     P0-T1
進行中 Task:       なし
次に実行する Task: P0-T2 code-pact を初期化し、P0 ロードマップを登録する
一度に実行する Task: 1 件
```

## 進行規則

- Agent は 1 回の実行で 1 タスクだけを処理する
- 先行するタスクの完了条件を満たさないまま、次のタスクへ進まない
- 将来 Phase の機能を先行実装しない
- Phase をまたぐ変更が必要になった場合は、実装前にロードマップを更新する

## P13 の開始条件

P13 は、次のいずれかが実際に発生するまで着手しない。

- 組織からホスティング提供の具体的な要望が届く
- 継続的な利用希望が複数確認される
- セルフホスト導入支援だけでは解決できない需要が確認される
- 運用費用を賄える契約の可能性がある

認知獲得だけを目的として、常設の公開環境を先行して用意しない。
