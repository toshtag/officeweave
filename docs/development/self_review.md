# OfficeWeave 自己レビュー

本書は、PR を出したあとに自分の差分を見る観点を定義する。

人のレビューを待たずに merge まで進める場合、ここが最後の関門になる。
実装したときの視点のまま読み直しても、同じ見落としをもう一度するだけである。
書く側ではなく、壊す側から読む。

## 1. 観点

```text
1.  Issue 外の変更が無い
2.  認証、認可、組織の境界
3.  transaction、巻き戻し、並行した操作
4.  通知、外部への送信、記録の保持
5.  秘密の値、token、本文が記録や監査へ混ざっていない
6.  migration が、既存のデータと新規の作成の両方で通る
7.  一覧の上限、候補を全件描いていないか
8.  日本語と英語が対称か
9.  操作の文書と実装が一致するか
10. 回帰テストが、修正を外すと意図した理由で落ちるか
```

該当しない観点は、非該当である理由を PR 本文へ書く。空欄にしない。
空欄は「見ていない」と「見た結果、関係なかった」を区別できない。

## 2. 10 番目の見方

回帰テストは、通ることより「外したときに落ちること」で価値が決まる。
落ちない、または別の理由で落ちるなら、その修正を守っていない。

確かめ方は、最終の木へ一時的に変異を入れ、対応するテストが期待した理由で
落ちることを見ることである。変異は commit しない。

準備の失敗（読み込めない、列が無い）で全件落ちる状態は、証拠にしない。
それは修正の有無ではなく、書き足したものの有無を見ているだけである。

## 3. 配送の規約

`script/check_delivery_contract` が、次を機械で確かめる。

```text
commit の題名が日本語である
commit と PR に、共同作者の付記や生成した道具の宣伝が入らない
比較のために持ち込んだ外部の固有名が入らない
```

3 つ目の照合は、語そのものをこのリポジトリへ書かずに行う。書けば、それ自体が
持ち込んだことになる。手元では `.officeweave-policy/restricted-patterns`、
継続的インテグレーションでは秘密の値から読む。どちらも無い場合は、その照合
だけを飛ばす。飛ばしたことは出力へ残す。

## 4. merge の条件

```text
必須の検証がすべて成功している
未解決のレビューが残っていない
自己レビューの全観点に結果か非該当の理由がある
```

満たす前に merge しない。履歴を書き換えない。強制的に push しない。
