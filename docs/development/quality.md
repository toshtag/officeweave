# OfficeWeave 品質基盤

本書は、コードの検査手段と実行方法を定義する。

検査はすべてローカルで実行する。
継続的インテグレーションは、検証手順が固まった最終工程で導入する。
手順が固まる前に組むと、実装途中の暫定手順が設定として固定される。

## 1. 書式検査

Ruby の書式は Rails 標準の設定を基本とする。

```bash
docker compose exec web bin/rubocop
```

自動修正は次のとおり。差分を確認してからコミットする。

```bash
docker compose exec web bin/rubocop --autocorrect
```

### 独自に追加した規則

追加は、判断が分かれて指摘が繰り返される箇所だけにとどめる。
規則を増やすほど、本質的でない差分が増える。

| 設定                       | 理由                                    |
| ------------------------ | ------------------------------------- |
| `TargetRubyVersion: 3.4` | 採用している版に合わせ、使用できない記法を指摘させる            |
| `NewCops: enable`        | 追加された規則を既定で有効にする。無効のままでは更新しても検査内容が変わらない |
| `Layout/LineLength: 120` | 上限がないと、条件を 1 行へ詰めた読みにくい記述が通る          |

### 検査対象から外しているもの

| 対象              | 理由                        |
| --------------- | ------------------------- |
| `db/schema.rb`  | 生成物であり、手で書式を整える対象ではない     |
| `vendor/`       | 外部由来のコードで、書式を変更する対象ではない   |

### 現時点で導入していないもの

ERB と CSS の書式検査は導入していない。

対象となる画面がまだ存在せず、実際の記述傾向が分からない段階で規則を決めると、
実装に合わない指摘が並ぶ。画面が増えた時点で、必要性を確認して判断する。

導入する場合は、依存追加の手順に従って PR 本文へ根拠を記録する。
