# OfficeWeave 品質基盤

本書は、コードの検査手段と実行方法を定義する。

検査はすべてローカルで実行する。
継続的インテグレーションは、検証手順が固まった最終工程で導入する。
手順が固まる前に組むと、実装途中の暫定手順が設定として固定される。

## 1. 書式検査

Ruby の書式は Rails 標準の設定を基本とする。

```bash
docker compose exec web bin/rubocop
```

自動修正は次のとおり。差分を確認してからコミットする。

```bash
docker compose exec web bin/rubocop --autocorrect
```

### 独自に追加した規則

追加は、判断が分かれて指摘が繰り返される箇所だけにとどめる。
規則を増やすほど、本質的でない差分が増える。

| 設定                       | 理由                                    |
| ------------------------ | ------------------------------------- |
| `TargetRubyVersion: 3.4` | 採用している版に合わせ、使用できない記法を指摘させる            |
| `NewCops: enable`        | 追加された規則を既定で有効にする。無効のままでは更新しても検査内容が変わらない |
| `Layout/LineLength: 120` | 上限がないと、条件を 1 行へ詰めた読みにくい記述が通る          |

### 検査対象から外しているもの

| 対象              | 理由                        |
| --------------- | ------------------------- |
| `db/schema.rb`  | 生成物であり、手で書式を整える対象ではない     |
| `vendor/`       | 外部由来のコードで、書式を変更する対象ではない   |

### 現時点で導入していないもの

ERB と CSS の書式検査は導入していない。

対象となる画面がまだ存在せず、実際の記述傾向が分からない段階で規則を決めると、
実装に合わない指摘が並ぶ。画面が増えた時点で、必要性を確認して判断する。

導入する場合は、依存追加の手順に従って PR 本文へ根拠を記録する。

## 2. 静的セキュリティ検査

アプリケーションのコードを対象に、既知の脆弱性の型を検出する。

```bash
docker compose exec web bin/brakeman --quiet --no-pager --exit-on-warn --exit-on-error
```

指摘が出た場合は、実装を修正して解消する。
検出結果を無視する設定を既定で持たない。無視の設定が増えるほど、検査の意味が薄れる。

誤検出であると判断した場合は、次を PR 本文へ記録したうえで対処する。

```text
指摘の内容
誤検出と判断した根拠
実際に到達し得ないことの説明
```

## 3. 依存の脆弱性監査

依存として取り込んでいるライブラリに、公開済みの脆弱性がないかを確認する。

```bash
docker compose exec web bin/bundler-audit
```

ブラウザーへ配信する外部スクリプトも同様に確認する。

```bash
docker compose exec web bin/importmap audit
```

### 脆弱性が見つかった場合

1. まず更新で解消する
2. 更新できない事情がある場合に限り、`config/bundler-audit.yml` へ識別子を列挙して除外する
3. 除外する場合は、影響を受けない理由、代わりに取っている対策、再確認する時期を PR 本文へ記録する

恒久的な除外を作らない。除外は期限付きの判断として扱う。

### 実行の頻度

- 依存を追加または更新したとき
- 版数の更新を検討するとき
- 最終工程で導入する継続的インテグレーションでは毎回

## 4. 検査が働いていることの確認

検査は「指摘が出ないこと」だけを見ていると、
設定の誤りで何も検査していない状態に気づけない。

書式検査、セキュリティ検査ともに、対象ファイル数と実行結果を確認する。
設定を変更した際は、意図的に指摘が出る状態を作り、検出されることを確かめる。
