# OfficeWeave 設定

本書は、実行時に設定できる環境変数と、稼働確認の方法を定義する。

設定値は環境変数で与える。設定ファイルを書き換える運用にしない。
書き換えを前提にすると、アップグレードのたびに利用者側の変更が失われる。

## 1. 環境変数

雛形は [.env.example](../../.env.example) にある。
複製して `.env` として使用する。`.env` はリポジトリへ含めない。

### データベース接続

| 変数                   | 必須                | 既定値                       | 内容                     |
| -------------------- | ----------------- | ------------------------- | ---------------------- |
| `DATABASE_HOST`      | いいえ               | `localhost`（コンテナ構成では `db`） | 接続先のホスト名               |
| `DATABASE_PORT`      | いいえ               | `5432`                    | 接続先のポート                |
| `DATABASE_USER`      | いいえ               | `officeweave`             | 接続に使う利用者名              |
| `DATABASE_PASSWORD`  | 本番環境では必須          | なし                        | 接続に使うパスワード             |
| `DATABASE_NAME`      | いいえ               | 環境ごとの既定名                  | 接続先のデータベース名            |
| `TEST_DATABASE_NAME` | いいえ               | `officeweave_test`        | テスト用のデータベース名           |
| `RAILS_MAX_THREADS`  | いいえ               | `5`                       | 接続プールの上限               |

### 組織

| 変数                  | 必須  | 既定値           | 内容    |
| ------------------- | --- | ------------- | ----- |
| `ORGANIZATION_NAME` | いいえ | `OfficeWeave` | 組織の名称 |
| `ORGANIZATION_CODE` | いいえ | `default`     | 組織の識別子 |

### 初期利用者

`bin/rails db:seed` で最初の利用者を作成する際に使用する。
利用者が既に存在する場合は何も行わない。

| 変数                      | 必須            | 既定値                        | 内容           |
| ----------------------- | ------------- | -------------------------- | ------------ |
| `INITIAL_USER_NAME`     | いいえ           | `管理者`                      | 表示名          |
| `INITIAL_USER_EMAIL`    | 運用環境では必須      | 開発環境のみ `admin@officeweave.test` | メールアドレス      |
| `INITIAL_USER_PASSWORD` | 運用環境では必須      | 開発環境のみ `officeweave`       | パスワード        |

運用環境で未設定の場合、利用者は作成されない。

### メール送信

`SMTP_ADDRESS` を設定すると送信を開始する。
未設定の場合、開発環境では `tmp/mails` へ書き出し、それ以外の環境では送信しない。
未設定のまま送信を試みると、待ち時間だけが増えて何も届かない。

| 変数                     | 必須            | 既定値                     | 内容                  |
| ---------------------- | ------------- | ----------------------- | ------------------- |
| `SMTP_ADDRESS`         | 送信する場合は必須     | なし                      | 送信サーバーのホスト名         |
| `SMTP_PORT`            | いいえ           | `587`                   | 送信サーバーのポート          |
| `SMTP_DOMAIN`          | いいえ           | なし                      | 送信時に名乗るドメイン         |
| `SMTP_USER_NAME`       | いいえ           | なし                      | 認証に使う利用者名           |
| `SMTP_PASSWORD`        | いいえ           | なし                      | 認証に使うパスワード          |
| `SMTP_AUTHENTICATION`  | いいえ           | なし                      | 認証方式                |
| `SMTP_ENABLE_STARTTLS` | いいえ           | `true`                  | 暗号化への切り替えを試みるか      |
| `MAIL_FROM`            | いいえ           | `officeweave@localhost` | 送信元のアドレス            |
| `APPLICATION_HOST`     | 送信する場合は必須     | なし                      | メール本文の URL に使うホスト名  |
| `APPLICATION_PROTOCOL` | いいえ           | `https`                 | メール本文の URL に使うプロトコル |

### 実行環境

| 変数          | 必須  | 既定値           | 内容                                   |
| ----------- | --- | ------------- | ------------------------------------ |
| `RAILS_ENV` | いいえ | `development` | `development` / `test` / `production` |

### コンテナ構成で使う値

`compose.yaml` だけが参照する。アプリケーションは参照しない。

| 変数                        | 既定値    | 内容                    |
| ------------------------- | ------ | --------------------- |
| `WEB_PORT`                | `3000` | ホスト側で公開するアプリケーションのポート |
| `DATABASE_PUBLISHED_PORT` | `5432` | ホスト側で公開するデータベースのポート   |

`DATABASE_PUBLISHED_PORT` はホスト側の公開ポートであり、
コンテナ間の接続には影響しない。

### 秘密情報の扱い

- パスワードと鍵をリポジトリへ含めない
- `config/master.key` と `.env` は追跡対象から除外している
- `.env.example` には置き換え前提の値だけを書く

## 2. 稼働確認

用途の異なる 2 つのエンドポイントを用意している。

| 経路        | 確認する内容                | 応答                          |
| --------- | --------------------- | --------------------------- |
| `/up`     | アプリケーションが例外なく起動できたか   | 起動していれば 200                 |
| `/health` | 依存先へ到達できているか          | 正常なら 200、到達できなければ 503       |

`/health` の応答は次の形式とする。

```json
{
  "status": "ok",
  "checks": { "database": "ok" },
  "checked_at": "2026-07-29T06:36:23Z"
}
```

- `status` は個々の確認結果をまとめた値
- `checks` は依存先ごとの結果
- 到達できない依存先がある場合、`status` と該当する `checks` の値が `error` になり、応答は 503 になる

どちらも認証を要求しない。監視側が資格情報を持たずに到達できる必要がある。

### 使い分け

- コンテナの再起動判定には `/up` を使う。依存先の一時的な不調で再起動させない
- 監視と通報には `/health` を使う。依存先の障害を検知できる

### 確認例

```bash
curl -s http://localhost:3000/health
```
