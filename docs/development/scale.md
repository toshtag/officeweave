# OfficeWeave 想定規模での測定

本書は、想定規模のデータの作り方と、測定した値を持つ。

測るのは 1 回の要求が読み込む量である。速さそのものは実行環境で変わるため、
値そのものより、規模を上げても増えないことに意味がある。

## 1. データの投入

規模は利用者の数で指定する。1 人あたり 25 件の記録を積む。

```bash
docker compose exec -T -e LOAD_SAMPLE_SCALE=400 web bin/rails officeweave:load_sample
```

規模 400 で、次の量になる。

```text
利用者        400 件
設備・備品     400 件
お知らせ    10,000 件
予定       10,000 件
予約       10,000 件
申請       10,000 件
文書       10,000 件
監査記録    10,000 件
```

専用の組織（`load-sample`）へ積む。既にある組織の記録には触れない。
何度実行しても同じ状態になる。足りない分だけを書き込む。

投入は開発用の構成に対して行う。配布用の構成へ積むと、業務のデータと
混ざったまま消せなくなる。

## 2. 測定

投入した組織の利用者でログインし、主要な画面を開く。

```text
利用者  measure@load-sample.invalid
```

読み込む量は応答の大きさで見る。1 回の要求が返す量が、その画面の上限である。

## 3. 測定した値

規模 400（主要な記録が 1 万件）での値である。開発用の構成、2 回目の要求。

| 画面 | 応答の大きさ |
| --- | --- |
| ホーム | 9 KB |
| お知らせの一覧 | 17 KB |
| 予定の一覧 | 16 KB |
| 予約の一覧 | 21 KB |
| 設備・備品の一覧 | 12 KB |
| 部門の一覧 | 6 KB |
| 文書の一覧 | 12 KB |
| 利用者の一覧 | 22 KB |
| ログイン中の端末 | 9 KB |
| 文書の分類の一覧 | 6 KB |
| 予定の作成 | 21 KB |
| 予約の作成 | 13 KB |
| お知らせの作成 | 8 KB |

いずれも記録の数に比例しない。1 ページ分、または期間の内側の 1 ページ分だけを
読むためである。

## 4. 上限を入れる前の値

同じ規模で、上限を入れる前の予定の一覧は 266 KB だった。開始日以降を上限なく
並べていたためである。期間を持たせ、その内側でもページ送りを持たせた結果が
上の 16 KB である。

## 5. 問い合わせの数

記録を増やしても問い合わせの数が増えないことは、
`test/controllers/list_query_count_test.rb` が固定する。記録を 1 件だけ足した
状態と、さらに増やした状態で数え、同じであることを確かめる。

絶対の件数は書かない。書くと、無関係な変更のたびに書き換えが要る。

## 6. 選択欄

利用者・部門・設備を選ばせる欄は、並べる候補に上限を置く（`Candidates`）。
上限を超える組織では、絞り込みで残りへ到達する。

規模 400 の組織で、予定の作成は 21 KB である。上限が無ければ、利用者 400 人
ぶんの入力欄がそのまま加わる。
