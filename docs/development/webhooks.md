# OfficeWeave 出来事の送信の設計

本書は、Webhook の送信でなぜその実装を選んだかを記録する。
設定の方法と運用上の挙動は [設定](../operations/configuration.md#webhook-の送信先) にある。

送信先は利用者が画面から登録する。つまり、この製品は**利用者が指定した宛先へ
サーバーから接続する**。組織の内側にある宛先を指定されれば、外から届かない
はずの場所へ、この製品を踏み台にして到達できる。以下はその前提で選んでいる。

## 拒否する範囲の決め方

IANA の special-purpose address registry を基準にする。外部から到達できない
用途のものと、IPv4 を内包する形式のものを対象とする。

埋め込まれた IPv4 を取り出して判定し直す形は採らない。取り出し方は形式ごとに
違い、新しい形式が増えれば取りこぼす。範囲ごと拒否すれば、形式が増えても
判定は変わらない。

廃止済みの site-local（`fec0::/10`）も残す。廃止は「使われない」ことを
意味しない。

## 送信の時点で名前解決をやり直す

保存の時点だけで検査すると、保存後に名前解決の結果が内部のアドレスへ
変わったときに通ってしまう。送信のたびに解決し直し、その結果の IP へ
接続先を固定する。

固定するのは、解決してから接続するまでのあいだに結果が変わる経路を塞ぐため
である。

## proxy を経由しない

`http_proxy` などの環境変数は使わない。proxy を経由すると、接続先を固定しても
実際の宛先は proxy の判断で決まる。固定した意味が無くなる。

## 3xx を追わない

`Location` へ再接続すると、検査を通った宛先から、検査していない宛先へ
連れて行かれる。応答の状態だけを記録する。

## 応答を読み捨て、量と時間を区切る

記録に残すのは状態だけである。ヘッダーも本文も使わない。

受け取る量の上限は、本文だけでなくステータス行とヘッダーを含めた全体に
掛ける。ヘッダーだけを膨らませる宛先を、本文の上限では止められない。

圧縮した応答は要求せず、返されても展開しない。本文を使わないため圧縮しても
得るものが無く、展開は小さい応答から大きな確保を生む。

1 回の操作の期限とは別に、全体の期限を置く。少しずつ返し続ける宛先は、
1 回ごとの上限に掛からない。

期限で切れた送信はやり直さない。やり直しても同じ結果になり、同じ待ち時間を
繰り返すだけである。

## 失敗の記録に宛先を残さない

区分ごとに決めた文面だけを残す。宛先、解決した IP、ポート、経路、送信内容、
署名は残さない。例外の文面もそのまま残さない。接続の失敗や TLS の失敗の
文面には宛先が入る。

記録は監査として読まれる。読める相手が、送信先の内部の構成を知れる状態に
しない。

## 許可した宛先でも検査を外さない

`WEBHOOK_PRIVATE_DESTINATION_ALLOWLIST` は、拒否する範囲の判定だけを外す。
URL の検査、名前解決、接続先の固定、TLS 証明書の検証はそのまま行う。
名前解決のすり替えへの対策は無効にならない。

許可の指定に完全な origin だけを認めるのも同じ理由である。ワイルドカードや
CIDR を認めると、意図した 1 つの宛先ではなく範囲が開く。

書式が不正な場合は、黙って無視せず送信をすべて拒否する。無視すると、
許可したつもりの宛先へ送れないことに気付かないまま運用が続く。
