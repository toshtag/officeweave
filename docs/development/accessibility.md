# OfficeWeave アクセシビリティ方針

本書は、画面が満たすべき最低要件と、確認方法を定義する。

利用者を選ばない業務基盤にするため、要件は後付けではなく画面を作る時点で満たす。

## 1. 最低要件

新しい画面を追加する際、次をすべて満たす。

### 構造

- 文書の言語を `html` 要素の `lang` で示す
- 見出し領域、本文領域、脚注領域を地標として示す
- 1 画面につき `h1` を 1 つ置き、見出しの階層を飛ばさない
- 反復する領域を読み飛ばして本文へ移動できるリンクを置く

### 操作

- すべての操作をキーボードだけで実行できる
- 焦点の位置が常に見える
- 焦点の移動順が、画面上の並びと一致する
- 操作の対象と目的が、周囲の文脈なしで分かる名前を持つ

### 表示

- 文字と背景の明度差を 4.5:1 以上にする
- 操作できる部品の輪郭と背景の明度差を 3:1 以上にする
- 色だけで意味を伝えない
- 利用者の文字サイズ設定を上書きしない
- 動きを減らす設定を尊重する

### 動作

- JavaScript が無効でも、登録、更新、削除、検索が完了する
- 自動で画面が切り替わったり、焦点が移動したりしない

## 2. 実装上の取り決め

### 隠し方

読み上げの対象に残したまま画面から隠す場合は、位置をずらす方法を使う。

`display: none` と `visibility: hidden` は、読み上げと焦点移動の対象からも外れる。
読み飛ばし用リンクのように、焦点が当たったときに現れるべき要素へ使ってはならない。

### 焦点の輪郭

`outline` を消さない。消すと、キーボード操作で現在位置が分からなくなる。
見た目を変える場合は、輪郭を別の表現へ置き換えたうえで、位置が分かる状態を保つ。

### 名前の付け方

操作の名前は、翻訳ファイルを経由して与える。
画面上の表記だけでは目的が伝わらない場合、補助的な名前を付ける。

言語の切り替えのように、選択肢そのものが別言語である場合は、
その要素へ `lang` を指定する。読み上げの発音が変わる。

## 3. 確認方法

### 自動で確認していること

`test/system/accessibility_test.rb` で次を確認している。

```text
読み飛ばし用リンクの存在と移動先
地標が一組ずつ存在すること
h1 が 1 つであること
文書の言語が示されていること
操作に説明が付いていること
選択中の状態が示されていること
```

### 手で確認すること

画面を追加した際は、次を実行する。

```text
キーボードだけで一連の操作を完了できるか
焦点の輪郭が常に見えるか
焦点の移動順が画面上の並びと一致するか
JavaScript を無効にしても操作が完了するか
```

### 明度差の確認

設計トークンの色を変更した際は、比率を計算して確認する。
現在の値は次のとおり。

```text
明るい表示
  本文 / 背景            14.96
  補助文字 / 背景         5.48
  強調色 / 背景           6.84
  操作部品の輪郭 / 背景     3.64

暗い表示
  本文 / 背景            15.45
  補助文字 / 背景         8.04
  強調色 / 背景           7.67
  操作部品の輪郭 / 背景     3.70
```

区切り線のような装飾のための線は、この基準の対象外とする。
