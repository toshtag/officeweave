# 組織の管理

利用者と組織の情報を預かる操作を扱う。断りのないものは管理者だけが行える。

環境の設定、監視、バックアップは [運用管理](../operations/administration.md) が持つ。
ここでは画面の操作だけを扱う。

## 利用者

### 見る

`/users` に、その組織の利用者が並ぶ。名前とメールアドレスで検索でき、部門と
状態で絞り込める。1 ページずつ読む。

一般の利用者はこの一覧を開けない。

### 追加する

`/users/new` で、名前・メールアドレス・役割・初期パスワードを入れる。

メールアドレスは組織をまたいで重ならない。既に使われている場合はその旨が出る。

役割は 2 つある。

```text
利用者  自分の仕事のために画面を使う
管理者  組織の情報と利用者を預かる。利用者ができることはすべてできる
```

### 無効にする・戻す

利用者の画面から無効にする。無効にすると次が同時に起きる。

```text
その利用者のログインがすべて終わる
発行済みの外部接続 token が使えなくなる
承認の委任が働かなくなる
```

有効に戻しても、失効した token は元に戻らない。発行し直す。

組織の管理者が自分ひとりになる状態は作れない。最後の管理者を無効にしようと
すると、その旨が出て止まる。役割を利用者へ変える場合も同じである。

この判定はデータベース上の行を占有して行う。2 人の管理者を同時に無効にしても、
どちらか一方だけが成立する。

### 監査に残ること

作成、更新、有効化、無効化はいずれも監査記録へ残る。

## 部門

### 見る

`/departments` に、その組織の部門が階層とともに並ぶ。1 ページずつ読む。

### 作る・直す

`/departments/new` で、名前・識別子・上位部門・並び順を入れる。

識別子は組織のなかで重ならない。上位部門を選ぶ欄には上限があり、多い組織では
絞り込んでから選ぶ。

自分自身や自分の下位を上位に指定することはできない。指定するとその旨が出る。
この判定はデータベース側でも行うため、画面を通らない経路でも循環は作れない。

### 所属を足す・外す

部門の画面から、利用者を足す。1 人につき 1 つの部門を主たる所属にできる。

利用者を選ぶ欄には上限がある。多い組織では、絞り込んでから選ぶ。

### 消す

配下の部門や所属がある間は消せない。先に外す。

## 利用者と部門の入出力

`/data_transfers` で、利用者と部門を CSV で取り込み、書き出す。

取り込みは 1 度の操作でまとめて確定する。1 行でも誤りがあれば、1 件も取り込まない。
どの行が誤っていたかは画面に出る。

書き出しには、その組織の記録だけが入る。

取り込みと書き出しはいずれも監査記録へ残る。

## 監査記録

### 見る

`/audit_events` に、重要な操作の記録が新しい順に並ぶ。操作の種類と実行者で
絞り込める。1 ページずつ読む。

記録は書き足すだけで、後から書き換えられない。個々の記録を選んで消す経路も
持たない。都合の悪い 1 件だけを取り除ける状態にしないためである。

記録の詳細には、本文やコメント、秘密、token を入れていない。監査は誰が何を
したかを追うためのものであり、業務の内容の写しではない。

### 書き出す

一覧の条件のまま CSV で書き出せる。1 度に書き出せる件数には上限がある。
超える場合は、絞り込むか、コマンドから書き出す
（[運用管理](../operations/administration.md#書き出し)）。

書き出したこと自体も記録へ残る。

### 残る期間

保持期間は環境の設定で決める（[設定](../operations/configuration.md#監査記録)）。
指定していない場合は消えない。

## 外部からの接続に使う token

### 発行する

`/api_tokens` で発行する。一覧は 1 ページずつ読む。扱えるのは自分の token
だけである。管理者であっても他人の token は発行できない。

```text
名前      用途が分かる名前
期限      30 日、90 日、365 日から選ぶ
読める範囲 お知らせ、予定、部門、利用者から選ぶ
```

値は発行の直後に 1 度だけ表示する。保存していないため、後から確認できない。
控えを取り忘れた場合は、失効させて発行し直す。

読める範囲は必ず選ぶ。選んだ範囲は発行の時点で決まり、後から資源が増えても
その token へ自動では開かない。新しい資源を読ませたい場合は発行し直す。

token の権限は発行した利用者から引き継ぐ。範囲はそれを狭めるだけで、広げない。
一般の利用者の token へ利用者の一覧を許しても、管理者だけが読めるものは読めない。

### 失効させる

一覧から失効させる。失効した token はすぐに使えなくなる。

発行と失効はいずれも監査記録へ残る。

## 出来事の送信先

### 登録する

`/webhook_endpoints` で、出来事を受け取る宛先を登録する。一覧は 1 ページずつ
読む。

```text
名前      用途が分かる名前
URL       送信先
秘密      署名の検証に使う値
出来事    受け取る出来事の種類
```

送信先には内部のアドレスを指定できない。指定した場合は、その理由の符号が
送信の記録に残る。許可する範囲は環境の設定で変えられる。

### 送信の結果を見る

宛先の画面に、送信の記録が新しい順に並ぶ。試行ごとに 1 件残る。何回試したかを
読み取れるようにするためである。

配送は at-least-once とする。相手が受理した直後に接続が切れた場合、同じ本文が
二度届くことがある。受け取る側は、本文の `event` と `occurrence` の組で
二度届いた分を捨てられる。本文には形の版も入っている。

送信の記録が残る期間は環境の設定で決める
（[設定](../operations/configuration.md#記録の保持)）。

登録、変更、削除はいずれも監査記録へ残る。
