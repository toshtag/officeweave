# はじめに

ログインから、自分に関わる設定までを扱う。

## ログイン

`/session` を開き、メールアドレスとパスワードを入れる。

利用者は自分で登録できない。管理者が作った利用者だけがログインできる。

失敗したときの文面は、利用者がいてもいなくても同じにしてある。違えると、
組織に属するメールアドレスの一覧をこの画面から作れてしまう。

短い時間に何度も失敗すると、しばらく受け付けなくなる。時間を置いてから
試す。数え上げは web の台数に依らないため、待ち時間は環境の規模で変わらない。

外部の認証基盤を使う設定では、パスワードの入力欄が出ない。代わりに認可
サーバーへ送り出す入口が出る。詳細は [認証方式](../development/authentication.md) にある。

## 入口

ログインすると `/` が開く。次の 4 つが並ぶ。

```text
未読のお知らせ    読んでいないものの件数と、直近の分
承認を待つ申請    自分が承認を担当していて、まだ決めていないもの
自分の申請        下書き、承認待ち、差し戻されたもの
所属部門          自分が属する部門。上位の階層まで出る
```

いずれも入口には抜粋だけを並べる。全件はそれぞれの一覧で見る。

## 自分の設定

`/settings` で、表示する言語と通知の受け取り方を決める。

```text
表示する言語        画面の語句に使う言語
メールで受け取る    出来事ごとに、画面の通知に加えてメールを受け取るか
```

画面の通知は、この設定に関わらず残る。設定が決めるのはメールだけである。

保存は 1 度の操作でまとめて行う。言語だけが変わって通知の設定が変わらない、
という状態は起きない。

## 通知

`/notifications` に、自分あての通知が新しい順に並ぶ。未読だけへ絞れる。

同じ出来事について二重には作られない。ただし、差し戻された申請を出し直した
場合や、同じ人が複数の段を担当する場合は、それぞれ別の通知になる。前の通知を
読んでいても、新しい未読として届く。

通知を開くと、その対象の画面へ移る。

## ログイン中の端末

`/logins` に、自分がログインしている端末が並ぶ。1 件ずつ終わらせるか、
いま使っている端末以外をまとめて終わらせられる。

いま使っている端末は、まとめて終わらせる操作の対象に入らない。自分を締め出す
操作を、一覧の主要な操作として置いていない。ログアウトは画面右上で行う。

他の利用者の端末は扱えない。管理者であっても、この画面から他人のログインは
終わらせられない。利用者を無効にする操作が、その利用者のログインをすべて
終わらせる（[組織の管理](organization.md#利用者)）。

期限を過ぎた記録は並ばない。認証には使えず、並べると終わらせる操作が必要に
見えるためである。

## パスワード

### 変更する

`/password` で、いまのパスワードと新しいパスワードを入れる。

いまのパスワードが違うと保存できない。変更すると、他の端末のログインは
すべて終わる。

### 忘れたとき

`/password_resets` でメールアドレスを入れると、案内のメールが届く。

送ったかどうかは画面に出ない。出すと、その住所の利用者がいるかどうかを
この画面から確かめられてしまう。

案内の値には期限があり、一度使うと再び使えない。パスワードを変えたあとも
使えなくなる。期限を過ぎた場合は、もう一度要求する。

再設定を終えても、そのままログイン状態にはならない。案内のメールを読める
相手が、そのままログインできる形にはしていない。

外部の認証基盤を使う設定では、この画面は出ない。資格情報がこの製品の中に
無いためである。

## 表示する言語の切り替え

画面右上で切り替える。JavaScript を使わずに完結する。

切り替えた言語は、次に開いたときも続く。利用者ごとの既定は
[自分の設定](#自分の設定) で決める。設定していない場合は、ブラウザーが送る
希望、それも無ければ日本語を使う。
