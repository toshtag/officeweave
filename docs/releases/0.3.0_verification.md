# 0.3.0 の検証

本書は、版 0.3.0 を本番準備済みと判定した根拠を持つ。

判定の条件は [受入条件](../product/acceptance_criteria.md) の「4. 実装済みと本番準備済み」にある。
条件ごとの判定は [機能到達度の一覧](../product/capability_registry.yml) が持つ。

## 対象

```text
版        0.3.0
commit    59be7b279106d62f7070852dceb7b7a1ee24b126
判定日     2026-08-07
```

`0.3.0` として公開する木は、この commit に本書と版数の更新を重ねたものである。
実測はすべて上記の commit に対して行った。

## 環境

実測は、開発用の構成とは別に作った、破棄できる環境で行った。開発用の
データベースに残る負荷測定用のデータは使っていない。

```text
構成      compose.production.yaml（配布用）
イメージ   Dockerfile.production から組み立て
ホスト     Darwin 25.5.0 / Docker Compose
データベース postgres:18.4-bookworm
```

環境は、測定を終えた時点で破棄した。

## 実測

### 一括検証

```text
bin/verify                                  exit 0    6 分 36 秒
  書式: Ruby                                473 files inspected, no offenses detected
  セキュリティ: 依存の脆弱性                   No vulnerabilities found
  セキュリティ: 静的解析                      No warnings found
  テスト: 全件（実ブラウザーを除く）             2105 runs, 9467 assertions, 0 failures, 0 errors
  テスト: 初期データ                          passed
```

並行の実行数を 1 にして走らせた。同じホストで他の環境も動いており、並行で
走らせるとデータベースが待ち合いを検出して落ちる。これは製品の欠陥ではなく
測定環境の混み具合であるが、記録として残す。

### 実ブラウザー

```text
bin/rails test:browser                      exit 0    45 秒
  24 runs, 161 assertions, 0 failures, 0 errors
```

まとめて実行した結果である。個別の実行では代えていない。

まとめ実行時だけ 6 件が落ちる状態が以前あった。原因は、横へ動かす箱が背景色を
持たず、箱の外へ出た列の文字が何の上に載っているかを解決できないことだった。
背景を明示して解消してある。背景を外すと 6 件が再現し、戻すと 0 件になることを
確かめた。

### 新規の導入

```text
配布用イメージの組み立て                       24 秒
docker compose -f compose.production.yaml up -d   44 秒（3 つとも healthy）
script/seed_initial_user --production          初期利用者を作成
bin/diagnose                                   exit 0
  確認 19 件、注意 1 件、失敗 0 件
```

注意の 1 件は `APPLICATION_HOST` が `localhost` であることによる。測定用の
環境の設定であり、実際の配布先では利用者が接続するホスト名を設定する。

### 取得と復元


書庫の中身を書き換えたものは復元の前に拒む。

```text
改変した書庫  exit 1「書庫の中身が取得したときと違います」
既存のデータ  触れていない（お知らせ 9500 件のまま）
```

要約が見つけられるのは、壊れと取り違えだけである。書庫ごと作り直されれば
要約も作り直せるため、意図して書き換えた相手は見つけられない。

### 診断のコマンド

```text
bin/diagnose                                 exit 0（失敗が無い場合）
bin/diagnose                                 exit 1（失敗がある場合）
秘密情報の値                                   出力に 0 件
```

失敗がある状態（管理者が未作成）で 1、解消後に 0 を返すことを実際に確かめた。
出力へ `DATABASE_PASSWORD`、`SECRET_KEY_BASE`、初期パスワードの値そのものが
現れないことも確かめた。
